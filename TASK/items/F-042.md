# F-042 — HTTP 401 não invalida o access token em cache; sync fica travado falhando por até ~1h

## F-042 | categoria: funcional | severidade: média | status: fixed
- Tela: Sources/Sync/GoogleCalendarAPI.swift:143-144 (401 → `.unauthenticated`); Sources/Sync/CalendarSyncService.swift:135 (só captura `syncTokenExpired`), :104-108 (`syncNow` engole o erro); Sources/Auth/GoogleAuth.swift:64-69 (`isValid`), :82-92 (`validAccessToken` devolve cache)
- Passos:
  1) Google rejeita o access token em uso (revogação, mudança de consent/escopo, clock skew) → 401.
  2) `get` lança `CalendarAPIError.unauthenticated` (:143).
  3) O `do/catch` da lane incremental só captura `.syncTokenExpired` (:135), então propaga para `syncNow`, cujo `catch { }` engole ("transitório, próximo poll retenta", :104-108).
  4) Próximo poll: `validAccessToken` devolve o MESMO token do cache enquanto `isValid` (expiração − 60s, :64-69) — 401 nunca limpa `cachedToken`.
- Esperado: um 401 deve invalidar o token em cache e disparar refresh/re-auth antes de reusar.
- Observado: o mesmo token rejeitado é reusado a cada poll → 401 em loop até o cache expirar naturalmente (até ~expires_in − 60s ≈ ~59 min). Sync fica silenciosamente parado, reuniões ficam desatualizadas e alertas param, sem erro visível. Não existe caminho de 401 → re-auth.
- (resolvedor) Correção [Auth/Sync worker]: needs-human — BLOQUEADO por contrato Core congelado. Lado Auth JÁ FEITO: adicionei `GoogleAuth.invalidateAccessToken()` (zera `cachedToken` → próximo `validAccessToken()` re-busca via refresh token). Lado Sync NÃO PODE ser ligado dentro da minha propriedade: `CalendarSyncService` só enxerga o protocolo `AuthProviding` (o target Sync depende só de Core, NÃO de Auth — Package.swift:28), então não há como chamar `invalidateAccessToken()` após o 401 sem adicionar `func invalidateAccessToken() async` ao protocolo `AuthProviding` em Sources/Core/AuthProviding.swift (mudança de assinatura Core, proibida a este worker). AÇÃO HUMANA: adicionar essa 1 linha ao protocolo Core; depois o catch de `.unauthenticated` em `CalendarSyncService.syncNow()` (comentado no código, com TODO F-042) invalida o cache e retenta 1x. `swift build --target Auth`/`--target Sync` verdes com o que foi feito.
- (integração serializada) FIXED: o contrato Core foi liberado nesta etapa. Feito end-to-end:
  1. `AuthProviding` (Sources/Core/AuthProviding.swift) ganhou `func invalidateAccessToken() async`. `GoogleAuth.invalidateAccessToken()` (síncrono, actor-isolado) já satisfaz a exigência `async` (acesso cross-actor é implicitamente async) — nenhuma outra conformância existe (só `GoogleAuth`), pacote compila.
  2. `CalendarSyncService.syncNow()` agora extrai `runSyncPass()` e faz `catch CalendarAPIError.unauthenticated` → `await auth.invalidateAccessToken()` + 1 retry. Um 401 passou a bustar o cache e re-buscar via refresh token no MESMO poll, em vez de reusar o token rejeitado por ~59 min. Falha persistente após o retry cai como transitória (próximo poll); refresh token morto continua tratado por F-041 (wipe + re-auth via Prefs).
  `swift build -c release` verde.
