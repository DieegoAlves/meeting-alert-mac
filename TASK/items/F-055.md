# F-055 — App continua mostrando eventos DEMO depois de colar o Client ID

## F-055 | categoria: funcional | severidade: alta | status: fixed
- Tela: Sources/App/AppDelegate.swift:60-68 (wiring demo vs sync), Sources/App/DemoFixtures.swift (flag/fixtures), Sources/Prefs/PreferencesView.swift:46-61 (salvar Client ID), Sources/Auth/LoopbackRedirectServer.swift (redirect OAuth), Sources/Auth/GoogleAuth.swift (Client ID + signIn).
- Passos (repro do Diego): 1) App rodando em modo demo (`open --env MEETINGALERT_DEMO=1`, PID observado 80806). 2) Colar o Client ID do Google em Preferências → Aplicar. 3) O menu-bar CONTINUA mostrando as reuniões falsas ("Standup (demo)", "1:1 em andamento", etc.); a agenda real nunca aparece.
- Esperado: com um Client ID salvo, o app entra em modo real, descarta os eventos demo e dispara o OAuth para popular a agenda de verdade.
- Observado — CAUSA-RAIZ (múltipla):
  1. **Demo preso na memória do processo.** `DemoFixtures.isEnabled` lê `MEETINGALERT_DEMO` do environment, que é fixado no launch. O processo em execução foi aberto com a flag → segue em demo até relançar. Salvar o Client ID não muda o processo vivo.
  2. **Demo tinha precedência incondicional sobre o sync.** `AppDelegate` fazia `if DemoFixtures.isEnabled { store.replaceAll(demo) } else { syncService.start() }` — em demo, o sync real NUNCA começa, mesmo com Client ID presente.
  3. **Eventos demo persistem no cache JSON.** `store.replaceAll(demo)` → `persist()` grava os fakes em `events.json` (no container do sandbox: `~/Library/Containers/com.disco-tec.MeetingAlert/Data/Library/Application Support/MeetingAlert/`). Num relançamento sem a flag, `store.load()` recarrega os fakes, e o merge incremental (`apply(upserts:removedIDs:)`) NUNCA os remove — o "calendário" demo nunca está na lista do Google, então nunca sofre a evicção de full-resync (F-040).
  4. **Salvar o Client ID não iniciava OAuth.** `commit()` só gravava no UserDefaults; `syncNow()` faz `guard await auth.isAuthorized` (falso até um sign-in interativo) → nenhum evento real. Não havia botão de "Conectar Google" nem gatilho automático.
  5. **BUG adicional descoberto na verificação — OAuth quebrado no macOS 26 (Darwin 25.6):** `LoopbackRedirectServer` usava `NWListener` (Network.framework) e falhava em bindar com **NWError 22 (EINVAL)** para QUALQUER configuração — inclusive `NWListener(using:.tcp,on:.any)` — dentro do app com sandbox, mesmo com a entitlement `com.apple.security.network.server` presente. Um socket POSIX bindado em `127.0.0.1:0` funciona no mesmo contexto (verificado in-app: READY port=58707). Sem loopback, o OAuth nem abre o navegador.
  6. **BUG adicional — newline no Client ID colado:** `commit()` fazia `trimmingCharacters(in: .whitespaces)`, que NÃO inclui `\n`. O paste do Diego carregava um `\n` no fim → o Client ID chegava ao Google como `…googleusercontent.com%0A` e o endpoint respondia `invalid_client — The OAuth client was not found`.

## Correção (root) — FIXED e verificado
1. **Demo é opt-in explícito e cede ao Client ID.** `DemoFixtures.isEnabled` agora retorna `false` sempre que há um Client ID salvo (real mode vence); a flag `MEETINGALERT_DEMO` só vale sem Client ID. (`Sources/App/DemoFixtures.swift`)
2. **Purga determinística dos eventos demo.** Todo evento demo é marcado com o `calendarId` reservado `demo@meeting-alert.local` (origem "demo"); ao entrar em modo real, `AppDelegate.purgeDemoEventsIfAny()` remove do EventStore/cache só os eventos com esse tag via `store.apply(upserts: [], removedIDs:)` — eventos reais intactos. (Sem editar o contrato congelado `CalendarEvent`/`EventStore`.)
3. **Salvar o Client ID entra em modo real na hora.** `PreferencesViewModel.commit()` posta `PreferencesEvents.clientIDSavedNotification` quando o ID (limpo) é não-vazio e mudou; `AppDelegate` observa e chama `enterRealMode()` (purga demo → `stop()`+`start()` do sync → `startOAuthIfNeeded()`), sem exigir relançamento.
4. **OAuth automático + botão explícito.** No launch em modo real com Client ID presente e sem credencial, `startOAuthIfNeeded()` abre o consentimento no navegador. Além disso há um item **"Conectar Google"** no menu (`MenuBarController.connectGoogleNotification` → `AppDelegate.connectGoogle()`) para (re)conectar sob demanda.
5. **LoopbackRedirectServer reescrito em sockets POSIX** (bind explícito em `127.0.0.1:0`, mantém a garantia loopback-only da F-043; preserva `waitForCode`/classificação CSRF da F-045). Agora binda e o navegador abre — verificado: `127.0.0.1:59804 (LISTEN)` + aba do Google aberta.
6. **Trim com `.whitespacesAndNewlines`** ao salvar (`commit`), ao consumir (`GoogleAuth.requireClientID`, que também REPARA um valor já salvo sujo sem re-colar) e em `DemoFixtures.hasClientID`.
7. **Erros de sync deixam de ser silenciosos.** `GoogleCalendarAPI.get()` loga status HTTP + corpo do erro do Google; `CalendarSyncService.syncNow()` loga a causa exata (não há fallback para demo).

## Verificação
- `swift build -c release` limpo. Processo demo (PID 80806) morto; app relançado SEM a flag (PID novo sem `MEETINGALERT_DEMO`). Cache: `events.json` sem nenhum evento `demo@meeting-alert.local`.
- OAuth: o navegador do Diego ABRE no fluxo do Google (loopback em `127.0.0.1:<porta>` ativo). `invalid_client` (newline) resolvido.
- **PENDENTE COM O GOOGLE (não é bug do app):** o Client ID `128917033994-…apps.googleusercontent.com` (projeto `gen-lang-client-0240319120`) é rejeitado com `invalid_request — "The loopback flow has been blocked… Follow the Loopback IP Address flow migration guide"`. Isso ocorre quando o cliente OAuth é do tipo **Web application**. Ação do Diego: criar/usar um Client ID do tipo **Desktop app** (App type "Desktop") no Google Cloud Console e colá-lo em Preferências — o fluxo loopback PKCE é o suportado para apps desktop. Completar o consentimento exige o Diego no navegador; após consentir, o sync real popula "Próximas".

## Como habilitar demo de propósito (futuro)
- Garanta que NÃO há Client ID salvo (Preferências → campo vazio → Aplicar, ou `defaults delete com.disco-tec.MeetingAlert MeetingAlertOAuthClientID`).
- Assemble o bundle e lance com a flag: `open --env MEETINGALERT_DEMO=1 .build/MeetingAlert.app`. Um evento demo dispara o overlay ~30 s após o launch. Sem Client ID salvo, a flag manda; com Client ID salvo, o modo real sempre vence.
