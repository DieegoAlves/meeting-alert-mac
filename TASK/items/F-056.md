# F-056 — "Erro 400: invalid_request" no login do Google (fluxo loopback)

## F-056 | categoria: funcional/auth | severidade: alta | status: fixed
- Tela: Sources/Auth/GoogleAuth.swift (monta a URL de autorização, PKCE, client_id), Sources/Auth/LoopbackRedirectServer.swift (listener loopback + callback), Sources/Prefs/PreferencesView.swift (campo do Client ID + superfície de erro).
- Passos (repro do Diego): 1) Colar o Client ID do Google em Preferências → Aplicar. 2) O navegador abre no Google. 3) A tela de LOGIN do Google mostra: "Acesso bloqueado: a solicitação do app Aviso de Reunião é inválida — Erro 400: invalid_request". Nunca chega ao consentimento.

## Auditoria da URL de autorização (item 1) — cada parâmetro conferido
URL exata que o app abre (client_id truncado; porta/challenge/state são amostras):
```
https://accounts.google.com/o/oauth2/v2/auth?client_id=128917033994-…nt.com&response_type=code&redirect_uri=http://127.0.0.1:59804&scope=https://www.googleapis.com/auth/calendar.events.readonly&code_challenge=E9Melhoa2Owv…&code_challenge_method=S256&state=95BF6151-…&access_type=offline&prompt=consent
```
- `response_type=code` ✓
- `redirect_uri=http://127.0.0.1:<porta>` ✓ — 127.0.0.1 (NÃO "localhost"), sem path espúrio, esquema http correto para loopback. A porta bate com o listener POSIX (getsockname).
- `scope=https://www.googleapis.com/auth/calendar.events.readonly` ✓ — escopo Google VÁLIDO; um único escopo (sem necessidade de %20); URLComponents deixa `:` e `/` literais, o que o Google aceita. (Não é vírgula-separado.)
- `code_challenge` (Base64URL sem padding, sem `+`/`/`/`=`) + `code_challenge_method=S256` ✓
- `state` (UUID) ✓ · `access_type=offline` ✓ · `prompt=consent` ✓
- SEM parâmetro vazio, SEM duplicado. **A URL NÃO está malformada.**
- Client ID salvo em disco conferido byte a byte (plist do sandbox, `plistlib`): `128917033994-8gsr76eened9oh2u811778eqfsohbp62.apps.googleusercontent.com` — 72 chars, **sem newline/whitespace**, sufixo `.apps.googleusercontent.com` único (não duplicado). O trim da F-055 está funcionando.

## Causa-raiz — NÃO é bug de código do app
O Google exibe o NOME do app ("Aviso de Reunião"), logo o `client_id` resolve → **não é `invalid_client`**. Com a URL 100% conforme e o id limpo, o `invalid_request` na própria tela do Google (antes de qualquer redirect ao loopback) tem uma causa só: **o cliente OAuth é do tipo "Aplicativo da Web" (Web application), não "App para computador" (Desktop app)**. O Google BLOQUEIA o fluxo de IP de loopback (127.0.0.1) para clientes Web e responde "Erro 400: invalid_request". É o mesmo projeto `128917033994` já sinalizado como PENDENTE na F-055. O fluxo loopback+PKCE que o app implementa é o CORRETO e é o suportado — mas só para clientes **Desktop app**. Correção real = Diego criar/usar um Client ID **Desktop app** no Google Cloud Console (ação só dele; escalado via overclock_clarify).

## Correção (root/app) — FIXED e compilado
Como a raiz é config do console (fora do código), o trabalho de app foi tornar a falha DIAGNOSTICÁVEL e nunca silenciosa (itens 1 e 5):
1. **Log da URL de autorização completa** com `client_id` truncado (`GoogleAuth.redactClientID` mantém todos os outros params intactos): `NSLog("[MeetingAlert] OAuth authorize URL: …")` em `signIn()`.
2. **Erros de OAuth agora chegam ao Diego.** `GoogleAuth` grava a última falha (mensagem exata + URL redigida) em UserDefaults (`MeetingAlertLastAuthError`/`MeetingAlertLastAuthURL`) e posta `Auth.signInFailed`/`Auth.signInSucceeded`. A janela de Preferências mostra um bloco laranja "Última falha de autorização" com o erro EXATO e a URL usada (texto selecionável), lendo tanto ao abrir quanto ao vivo. Sucesso limpa o bloco. (`AuthDiagnostics` em GoogleAuth.swift; observers em PreferencesViewModel; UI na seção "Google OAuth".)
3. **Callback de erro deixa de travar 5 min.** `LoopbackRedirectServer.classify` passa a detectar `?error=…&error_description=…` no callback e retorna `.error`; o accept-loop envia uma página 400 ao navegador e aborta o fluxo IMEDIATAMENTE com o motivo exato, em vez de ignorar (sem `code`) e esperar o timeout de 5 min.
4. **Texto de ajuda no campo do Client ID** avisa para usar cliente **"App para computador" (Desktop app)** — clientes Web são bloqueados no loopback.
