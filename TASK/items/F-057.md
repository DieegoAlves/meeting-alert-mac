# F-057 — Login OK mas ZERO eventos: troca código→token falha (HTTP 400, falta client_secret)

## F-057 | categoria: funcional/auth+sync | severidade: alta | status: fixed
- Tela: Sources/Auth/GoogleAuth.swift (troca de código→token, refresh), Sources/Sync/GoogleCalendarAPI.swift (classificação 403), Sources/Sync/CalendarSyncService.swift (status de sync), Sources/Core/SyncStatus.swift (NOVO surface), Sources/Prefs/PreferencesView.swift (campo Client Secret + status), Sources/MenuBar/MenuBarView.swift (estado vazio explícito).
- Passos (repro do Diego): 1) Criar cliente OAuth "App para computador" (Desktop app) e colar só o Client ID. 2) "Conectar Google" → chega ao CONSENTIMENTO, consente, o navegador mostra "Authorization complete". 3) O app segue mostrando ZERO eventos; "Próximas" vazio.

## Erro EXATO (lido da tela do Diego + do surface F-056)
Preferências → "Última falha de autorização": **"Authorization code exchange failed (HTTP 400)."** com a URL de autorização correta (Desktop app, `redirect_uri=http://127.0.0.1:58475`, `scope=…/calendar.events.readonly`, `code_challenge_method=S256`, `access_type=offline`, `prompt=consent`). Client ID novo `128917033994-g330…apps.googleusercontent.com`. NÃO é erro da Calendar API (não é 403/accessNotConfigured/events.list) — é a troca OAuth de **código→token** em `oauth2.googleapis.com/token` retornando HTTP 400.

## Causa-raiz
O `exchangeCode` do app enviava só `client_id` + PKCE (`code_verifier`), SEM `client_secret`. **O endpoint de token do Google EXIGE `client_secret` para um cliente "App para computador" (Desktop app), mesmo com PKCE.** Sem ele → HTTP 400 (`invalid_request`/`invalid_client`) → nenhum refresh token salvo no Keychain → `isAuthorized == false` → o sync aborta em "não autorizado" → zero eventos. O Diego achou que "conectou" porque a página de sucesso do loopback ("Authorization complete") é enviada QUANDO o code chega, ANTES da troca de token falhar. (A UI antiga ainda dizia "Apenas o Client ID — nunca o client secret", reforçando o erro.)

## Erro EXATO confirmado (após capturar o corpo do endpoint de token)
Com o novo captura de corpo, o app registrou o texto literal do Google:
**"Authorization code exchange failed (HTTP 400). invalid_request — client_secret is missing."** — prova definitiva da causa-raiz.

## Correção (root) — FIXED, `swift build -c release` limpo, relançado sem demo
1. **Enviar `client_secret` na troca e no refresh.** `GoogleAuth.exchangeCode` e `refreshAccessToken` agora incluem `client_secret` quando salvo (`optionalClientSecret()`). O secret é lido do **Keychain** (ver F-058), não de UserDefaults. (`Sources/Auth/GoogleAuth.swift`)
2. **Campo "Client Secret" em Preferências** (SecureField, com badge "salvo no Keychain") + texto atualizado explicando que o Google exige o secret na troca de token; salvar o secret re-dispara o modo real (`clientIDSavedNotification` agora dispara se id OU secret mudou). (`Sources/Prefs/PreferencesView.swift`)
3. **Erro EXATO do endpoint de token capturado e exibido.** `postToTokenEndpoint` lê o corpo `{"error","error_description"}` (`parseOAuthErrorDetail`), loga e propaga em `AuthError.tokenExchangeFailed(statusCode:detail:)`/`tokenRefreshFailed(...:detail:)`; o surface F-056 mostra "HTTP 400 — invalid_request: client_secret is missing" em vez de só "HTTP 400".
4. **Surface de STATUS de sync (novo, `Sources/Core/SyncStatus.swift`).** `SyncStatusCenter` (persistido em UserDefaults `MeetingAlertSyncStatus`) registra última tentativa/sucesso, nº de calendários, nº de eventos e o erro EXATO. Preferências → "Sincronização" mostra "Última sincronização há X min · N calendário(s)", "Eventos na janela" e, se houver, o erro (com botão de ação quando aplicável). Nunca mais cego.
5. **403 classificado corretamente (correção adicional).** `GoogleCalendarAPI.get` deixa de tratar TODO 403 como rate-limit (5× backoff, ~2 min desperdiçados) e depois rotular "rateLimited". Agora: `accessNotConfigured`/SERVICE_DISABLED → `apiDisabled(message, enableURL)` (terminal, extrai o link de ativação da Calendar API do corpo do Google); reasons de quota → backoff/retry; demais 403 → `forbidden(message)`. Mensagens exatas mapeadas em `CalendarSyncService.describe`.
6. **Estado vazio EXPLÍCITO no menu.** `MenuBarView`: se o último sync falhou → "Sincronização falhou" + erro + "Abra Preferências"; senão → "Nenhum evento até amanhã · última sync há X min" (em vez de menu em branco). (`Sources/MenuBar/MenuBarView.swift`)
