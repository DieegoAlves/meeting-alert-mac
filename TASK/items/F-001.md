# F-001 — "59.8 MB idle" não fura o budget: phys_footprint real = 20 MB (PASSA)

## F-001 | categoria: performance | severidade: alta | status: wont-fix
- Tela: research/03-performance-memory.md:4 ; research/03-performance-memory.md:257 ; scripts/measure-footprint.sh:8
- Passos:
  1) Build Release: `swift build -c release` ; empacotar `.app` e `open`.
  2) Deixar idle ~60s (menu fechado, sem overlay). PID 47080.
  3) Rodar os comandos abaixo e comparar phys_footprint vs RSS contra o budget.
- Esperado: o budget definido em research/03 é `< 30 MB resident (phys_footprint)`. Métrica de aprovação = **phys_footprint**, não RSS. Citação verbatim:
  - research/03:4 → "**Hard targets**: < 30 MB resident (phys_footprint), ~0% CPU at idle…" (o "resident" é definido, entre parênteses, COMO phys_footprint)
  - research/03:257 → "**Pass condition**: `phys_footprint < 30 MB` at idle (menu closed, no overlay)."
  - research/03:287 (tabela QA) → "| Idle phys_footprint | `sudo footprint -p MeetingAlert` | < 30 MB |"
  - scripts/measure-footprint.sh:8 → "# Budget : phys_footprint < 30 MB at idle"
  Logo: o budget É phys_footprint. NÃO é RSS.
- Observado: phys_footprint idle = **20 MB** (peak 21 MB) → PASSA com ~10 MB de folga. RSS = 61.6 MB é a métrica ERRADA (inclui páginas limpas/compartilhadas do dyld shared cache que o kernel não cobra do processo). Raw (macOS 26.6.2, ARM64, Release, idle ~60s, PID 47080), comandos + saída:
  ```
  $ ps -p 47080 -o rss= | awk '{printf "%.1f MB\n", $1/1024}'
  61.6 MB                              # RSS — NÃO é o budget

  $ footprint -p MeetingAlert          # (sem sudo — funciona p/ processo próprio)
  MeetingAlert [47080]: 64-bit    Footprint: 20 MB (16384 bytes per page)
      phys_footprint: 20 MB            # <<< métrica do budget → PASSA (<30)
      phys_footprint_peak: 21 MB

  $ vmmap 47080 | grep -E 'Physical footprint'
  Physical footprint:         20.1M    # confirma independente do footprint
  Physical footprint (peak):  21.3M

  $ top -pid 47080 -l 3 -s 2 -stats cpu,mem
  %CPU MEM
  0.0  20M                             # CPU idle 0.0% + mem(footprint)=20M
  ```
  Três ferramentas Apple concordam: phys_footprint ≈ 20.1 MB. O gap RSS(61.6) − footprint(20.1) ≈ 41 MB é 100% páginas COW compartilhadas de SwiftUI(36 regiões vmmap)+AppKit(17): `__OBJC_RO` 39.4M, `__AUTH_CONST` 28.3M, `__DATA_CONST` 15.9M residentes, todas `SM=COW`. O binário próprio é minúsculo (`__TEXT` 464K residente).
  → SE o budget fosse RSS, 61.6 MB > 30 = FALHA e seria piso quase inevitável de app SwiftUI-híbrido (ver F-004). Mas research/03 define phys_footprint; então PASSA.

- (resolvedor) Correção: wont-fix — nenhum defeito de código. O app já passa o budget de phys_footprint (20 MB < 30 MB); o "problema" era erro de medição no script (RSS != phys_footprint). Nenhuma alteração em Sources/.
