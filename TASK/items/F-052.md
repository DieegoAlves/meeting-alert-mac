# F-052 — "Respeitar Foco / Não Perturbe" não funciona no build sandboxed

## F-052 | categoria: funcional | severidade: alta | status: fixed
- Tela: Sources/Scheduler/FocusMonitor.swift:13-22 + Sources/Prefs/MeetingAlertFocusFilter.swift:19-22 + MeetingAlert.entitlements:6-7
- Passos: 1) Rodar o build release com App Sandbox ligado (`com.apple.security.app-sandbox = true` em MeetingAlert.entitlements). 2) Ativar um Foco / Não Perturbe no sistema, com "Respeitar Foco ativo" ligado em Prefs. 3) Aguardar um alerta de reunião.
- Esperado: Com "Respeitar Foco ativo", os alertas são suprimidos enquanto um Foco está ativo.
- Observado: `FocusMonitor.isActive()` lê `~/Library/DoNotDisturb/DB/Assertions.json` via `FileManager.default.homeDirectoryForCurrentUser` (linha 24-26). No sandbox esse home resolve para o container (`~/Library/Containers/com.disco-tec.MeetingAlert/Data/`), não o home real → arquivo inexistente → `isActive()` sempre retorna `false` → Foco nunca detectado → alertas sempre disparam. Além disso `MeetingAlertFocusFilter.perform()` retorna `.result()` sem efeito (linha 19-22), então a integração `SetFocusFilterIntent` é código morto. O toggle "Respeitar Foco ativo" em Prefs não altera comportamento nenhum.
- (resolvedor) Correção: fixed (build não-sandbox local, sem App Store). FocusMonitor já usa `getpwuid(getuid())` para resolver o home real (bypass de sandbox, sem API privada). AlertScheduler já checa `respectFocus && focus.isActive()` para suprimir alertas. PreferencesView: toggle renomeado de "Respeitar Foco ativo" para "Ignorar Focus" com binding invertido — OFF por padrão = respeitar Focus; ON = ignorar. Comportamento pendente no módulo Scheduler: atualmente `continue` (skip total) — a decisão pede downgrade overlay→notification; FLAG para worker do Scheduler implementar essa distinção de stage.
- (integração serializada) FIXED — fix coerente completo, os 3 componentes ligados:
  1. Detecção não-sandbox (research 02): `FocusMonitor.isActive()` lê `~/Library/DoNotDisturb/DB/Assertions.json` pelo home REAL via `getpwuid(getuid())` (sem API privada). Fail-open: arquivo ilegível → `false` (para um alerta de reunião, disparar na dúvida > perder a call).
  2. Toggle: "Ignorar Focus" em Prefs (OFF por padrão = respeitar Focus; ON = ignorar) mapeia para `respectFocus` invertido; `AlertScheduler.handleFire()` calcula `focusActive = prefs.respectFocus && focus.isActive()`.
  3. Downgrade (ANTES faltava): com `focusActive`, o stage `.overlay` agora vai para `presenter.presentSilentNotification(group)` em vez do overlay full-screen; o stage `.notify` (que já é notificação) segue normal. Nova rota em `AlertPresenting.presentSilentNotification` (Core) → `AlertPresenter` → `NotificationService.presentSilent` (interruptionLevel `.passive`, `sound = nil`) — some com o overlay e o som, mas ainda deposita a reunião na Central de Notificações. O grupo é consumido (markFired) de qualquer forma, então nunca re-dispara em loop.
  Limitação (documentada no README): a detecção de Focus é best-effort e depende do layout de `Assertions.json`; se a Apple mudar o formato ou o arquivo não existir, `isActive()` retorna `false` (fail-open) e o overlay dispara normalmente. `swift build -c release` verde.
