# F-003 — `swift build -c release` emite 9 warnings de linker (search path do CommandLineTools inexistente)

## F-003 | categoria: funcional | severidade: baixa | status: wont-fix
- Tela: Package.swift (linker, sem arquivo:linha de origem — são warnings de ld, não de código) ; log de `swift build -c release`
- Passos:
  1) `swift build -c release` num ambiente onde o dev dir ativo é o Command Line Tools (`xcode-select -p` → `/Library/Developer/CommandLineTools`).
  2) Contar os warnings no log (`grep -c "warning:"` → 9).
- Esperado: build limpo, zero warnings.
- Observado: 9 warnings, todos de linker, 1 por target, de duas formas — build mesmo assim conclui verde (`Build complete!`, exit 0). Zero warnings de compilador (`warning:` de código = nenhum). Trechos citados do log:
  ```
  Package.swift: Core:               ld: warning: search path '/Library/Developer/CommandLineTools/Developer/Library/Frameworks' not found
  Package.swift: Auth/AlertUI/Prefs/Sync/MenuBar/Scheduler: (mesmo warning, 1 por target)
  Package.swift: MeetingAlert-product: ld: warning: search path '/Library/Developer/CommandLineTools/Developer/usr/lib' not found
  Package.swift: MeetingAlert-product: ld: warning: search path '/Library/Developer/CommandLineTools/Developer/Library/Frameworks' not found
  ```
  Causa: o layout do Command Line Tools não tem `Developer/Library/Frameworks` nem `Developer/usr/lib` que a lista default de busca do ld espera (existem sob um `Xcode.app` completo). É ambiental — não adiciona nenhum byte ao binário nem ao runtime.
- Custo pro usuário: nenhum — ruído de build; só polui log de CI e pode mascarar um warning real futuro.
- (resolvedor) Correção:

Correção sugerida: (1) apontar pra Xcode completo se existir: `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer` e rebuildar; (2) se só há CLT, os warnings são inofensivos — documentar em README-scaffold.md como esperados; (3) NÃO silenciar com `-L` fixo no Package.swift (hard-code de path por-máquina, pior que o warning cosmético).

- (integração serializada) WONT-FIX — justificativa: os 9 warnings são 100% ambientais do linker (`ld: warning: search path '.../CommandLineTools/Developer/...' not found`), emitidos porque o toolchain ativo é o Command Line Tools em vez de um Xcode.app completo. Zero warnings de compilador; `Build complete!`, exit 0; nenhum byte adicionado ao binário. As duas únicas "correções" reais são (a) instalar o Xcode completo + `xcode-select -s` (decisão de ambiente da máquina, fora do código) ou (b) hard-codear `-L` por-máquina no Package.swift, que é PIOR (quebra em qualquer outra máquina). Documentado em README-scaffold.md como esperado sob Command Line Tools. Confirmado nesta etapa: o `swift build -c release` final continua com exatamente esses 9 warnings ambientais e nenhum de código.
