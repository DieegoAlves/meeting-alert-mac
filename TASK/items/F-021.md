# F-021 — titleTimer é um segundo timer sempre armado; viola o orçamento de "um único timer"

## F-021 | categoria: performance | severidade: média | status: fixed
- Tela: `Sources/MenuBar/MenuBarController.swift:22-23` / `:66-71` / `:107-110` / `:133-141` + `ARCHITECTURE.md:140` / `:146` / `:148` (contraste: `Sources/MenuBar/MenuBarView.swift:10-25`)
- Passos: 1) App ocioso, popover fechado. 2) Falta <60s p/ a próxima reunião → `computeTitle().needsSecondTick == true` e `titleTimer` passa à cadência de 1s. 3) Nada em tela, mesmo assim o app acorda a cada segundo.
- Esperado: exatamente um timer armado em idle e o countdown por segundo escopado só ao menu/popover aberto — `ARCHITECTURE.md:146` ("exactly one armed timer; zero windows at idle"), `:148` e `:140` ("per-second countdown timer runs only while the menu/popover is open").
- Observado: `private var titleTimer: DispatchSourceTimer?` (22-23) é um segundo timer persistente, armado incondicionalmente em `install()` (66-71) e vivo por toda a vida do app; `armTitleTimer` agenda um `DispatchSourceTimer` **repeating** (133-141) com cadência `1s` quando `< 60s` p/ reunião senão `60s` (107-110), independente da visibilidade do popover. Em idle há ≥2 timers armados (`AlertScheduler.timer` + `titleTimer`), violando "exactly one armed timer". O `MenuBarClock` (MenuBarView.swift:10-25) já é corretamente escopado ao popover — este é o timer extra. **Impacto p/ usuário: a CPU acorda a cada segundo no último minuto antes de cada reunião mesmo sem nada em tela, corroendo a promessa de ~0% CPU / <30 MB em idle.**
- (resolvedor) Correção: Adicionado `isPopoverOpen: Bool`; `refreshTitle()` usa `(needsSec && isPopoverOpen) ? 1 : 60` para o intervalo — o timer nunca dispara a 1 s com o popover fechado. `popoverWillShow` seta a flag e chama `refreshTitle()` para trocar imediatamente para 1 s se necessário; `popoverDidClose` reseta para 60 s. `install()` sempre inicia com 60 s (remoção da ramificação eager). NSPopover movido para `makePopover()` lazy (ver F-004).
