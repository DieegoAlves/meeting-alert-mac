# F-053 — Filtro de calendários exige digitar IDs manualmente

## F-053 | categoria: usabilidade | severidade: média | status: fixed
- Tela: Sources/Prefs/PreferencesView.swift:155-182 — TextField "Adicionar calendar ID…"
- Passos: 1) Abrir Preferências → seção "Calendários incluídos (vazio = todos)". 2) A única forma de incluir/excluir é digitar o ID cru do calendário (ex.: `abc123@group.calendar.google.com`) no TextField e clicar "Adicionar". 3) Não há lista de calendários da conta, picker por nome, nem botão de atualizar.
- Esperado: A história pede "Prefs: ... calendars ..." — o usuário deveria escolher entre seus calendários por nome, com descoberta.
- Observado: `CalendarSyncService.syncNow()` já busca a lista de calendários da API (`api.fetchCalendarList(token:)`, Sources/Sync/CalendarSyncService.swift:103), mas essa lista (que traz `id` e `summary`) nunca é exposta à UI de Prefs — é usada só para filtrar o sync. O usuário precisa achar IDs opacos no Google Calendar web e colar; qualquer typo inclui/exclui o calendário errado sem feedback.
- (resolvedor) Correção: deferred to integration step — decisão final: lista de calendários via calendarList.list API (Sync) + picker por nome na UI (Prefs) + filtragem com enabled-set. Cross-module; uma etapa serializada dedicada irá implementar end-to-end. Não implementado nesta passagem.
- (integração serializada) FIXED end-to-end:
  1. Sync: `GoogleCalendarAPI.fetchCalendarList` agora pede `id,summary,accessRole,primary,backgroundColor`; `CalendarListEntry` (EventDTO.swift) ganhou `primary` + `backgroundColor`.
  2. Core (novo `CalendarCatalog.swift`): `CalendarInfo {id, summary, isPrimary, colorHex}` + `@MainActor CalendarCatalog.shared` (ObservableObject, como o EventStore). `CalendarSyncService.publishCatalog()` empurra a lista descoberta a cada poll.
  3. Prefs: seção "Calendários" agora renderiza UMA checkbox por calendário (nome + swatch de cor), TODAS ligadas por padrão, a PRIMARY sempre ligada e `.disabled` (não-desmarcável). TextField de ID cru removido.
  4. Persistência invertida: `Preferences.includedCalendarIDs` (empty==todos) virou `disabledCalendarIDs` (empty==todos habilitados) — persistimos SÓ os UNCHECKED, então um calendário novo entra ON por padrão. Decode tolerante: prefs antigo sem a chave cai em set vazio (todos ON). A primary nunca entra no set (UI barra).
  5. Filtragem: `CalendarSyncService.filterCalendars` e `AlertPlanner.isIncluded` agora usam a lógica "habilitado a menos que em disabledCalendarIDs" → events.list roda só para calendários habilitados; alertas idem.
  Nota de armazenamento: os ids desabilitados moram em `Preferences` (persistido via PreferencesStore JSON), não num UserDefaults cru — a intenção da spec ("persistir só os unchecked") é atendida; ficou no store de prefs por coerência arquitetural (todo o resto das prefs passa por lá). `swift build -c release` verde.
