## Costura (root) — FIXED

Persistido no JSON de `Preferences` via `decodeIfPresent` (prefs antigo carrega com defaults, sem falha). Conversão `RGBAColor↔Color` fica nos módulos de UI (Core continua Foundation-only).

## Opções entregues por grupo

### GRUPO 1 — Aparência
- **Cor de fundo** (color well) + **opacidade** (slider 30–100%, default 82% = atual).
- **Tema** claro/escuro/automático — controla a paleta do TEXTO (escuro=texto claro=atual; automático segue a aparência do sistema no momento do build). Default escuro.
- **Tamanho do texto** pequeno/médio/grande — escala TODA a rampa de tipos (0.85/1.0/1.2). Default médio.
- **Cor do botão Entrar** (color well) com opção **"cor do sistema"** (nil = accent do sistema, default).

### GRUPO 2 — Conteúdo exibido (toggle OFF REMOVE a view, não só esconde)
- **Participantes** (contagem + avatares por iniciais em círculos) — default ON (atual).
- **Descrição** (truncada em N linhas, stepper 1–10) — default OFF.
- **Local** — default OFF.
- **Nome do calendário** com a cor do calendário (via `CalendarCatalog`) — default OFF.
- **Contagem regressiva** — default ON (atual).
- **Link da chamada como texto** — default OFF.
(Título e horário permanecem sempre visíveis — não estão na lista de toggles do pedido.)

### GRUPO 3 — Modo e posição
- **Tela cheia** (default, atual) vs **janela flutuante** compacta: NSPanel não-ativante, `level .floating`, tamanho fixo (440×300), MESMO conjunto de botões (Entrar + Já estou na call) e MESMOS atalhos.
- **Posição** da flutuante: 4 cantos ou centro, com **margem** configurável (default canto superior direito, margem 24 pt).
- **Monitores**: todos (default/atual) vs apenas principal vs onde está o mouse.
- **Fechar automaticamente após X s** (0 = nunca, default). No auto-close = MESMO caminho do "Depois" (`onDismiss` → `scheduler.dismiss`), então evento real é registrado no histórico normalmente. Timer de auto-close vive só enquanto o overlay está na tela.

### GRUPO 4 — Som e snooze
- **Volume** (slider 0–100%) independente do volume do sistema via `AVAudioPlayer.volume`; sons do sistema carregados de `/System/Library/Sounds/<nome>.aiff` para o mesmo controle (fallback NSSound quando o AVAudioPlayer não abre).
- **Repetir som a cada N s** até interação (0 = uma vez). Timer só durante a reprodução.
- **Escolher arquivo** (mantido do F-063) + **Pré-ouvir som** no volume configurado.
- **Tempos de snooze configuráveis** (3 campos, default 1/3/5, faixa 1–60). Atalhos de teclado seguem os valores.

## Decisões de produto tomadas (SIMPLES, registradas aqui — não escaladas)
1. **Tema × cor de fundo**: independentes. Tema define a paleta do TEXTO/cards; a color well define o backdrop. Os defaults (escuro + preto 82%) reproduzem o atual. Se o usuário escolher fundo claro com tema escuro (texto claro) o contraste fica por conta dele.
2. **Snooze × contrato Core congelado**: `AlertContracts.swift` (protocolo `AlertScheduling`, enum `SnoozeInterval`) NÃO foi alterado. Os 3 casos `.one/.three/.five` viram TOKENS POSICIONAIS de slot (0/1/2); o valor real vem de `overlayOptions.snoozeMinutes`. Com o default [1,3,5] o comportamento é idêntico ao anterior.
3. **Atalhos de snooze seguem os valores** só para valores de 1 dígito (1–9); valores ≥10 ficam só no clique/legenda (não há tecla única "10"). Mapeados por `charactersIgnoringModifiers` (mais robusto que keyCode fixo).
4. **Flutuante + "todos os monitores"**: uma única janela flutuante não cobre todas as telas, então `.all`/`.primary` → tela principal; `.mouse` → tela do mouse.
5. **Flutuante = tamanho fixo 440×300**; conteúdo escala compacto (~0.5 da rampa) para caber.
6. **Evento de teste enriquecido** (participantes/local/descrição/link) para o botão "Testar alerta" exercitar de fato os toggles do GRUPO 2. Continua fora do `EventStore`/histórico (id reservado `meeting-alert.test-alert`).

## Preview ao vivo / re-aplicação
Os controles da "Tela de aviso" gravam no store IMEDIATAMENTE (padrão F-053, não ficam atrás do "Aplicar"). O observer de `preferencesStore.$preferences` que já existe no `AppDelegate` chama `presenter.reapplyOverlayOptions()`: se um overlay (real ou de teste) está na tela, re-aplica AO VIVO sem relançar — mudanças de conteúdo/aparência re-renderizam via `@Published options`; mudanças estruturais (modo/monitor/posição/auto-close) reconstroem só os painéis (sem reiniciar som nem contagem). No-op quando não há overlay → ZERO trabalho em idle. "Restaurar padrão" reseta `overlayOptions = .default`.

## Performance
- **Sem novo timer/observer/view em idle**: opções lidas só no build do overlay; auto-close e repetição de som são timers que existem apenas enquanto o overlay está na tela; a re-aplicação pega carona no observer de Preferences que já existia. `AVAudioPlayer` é criado no disparo e liberado no `stop()` (nenhum engine de áudio vivo em idle).
- **phys_footprint idle antes/depois = 17,00 MB** (orçamento < 30 MB) — `./scripts/measure-footprint.sh` PASS nas duas medições. Sem regressão em relação aos ~18 MB de referência.
