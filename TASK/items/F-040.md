# F-040 — Sync mistura lane incremental com full-resync e o replaceAll apaga eventos de outros calendários

## F-040 | categoria: funcional | severidade: alta | status: fixed
- Tela: Sources/Sync/CalendarSyncService.swift:116 (flag global `didFullSync`), :132 (upserts incrementais), :141 (410 seta didFullSync=true), :160-167 (`store.replaceAll` vs `apply`)
- Passos:
  1) Usuário tem 2+ calendários incluídos, ambos já com syncToken persistido.
  2) Um poll roda: calendário A pega a lane incremental (só deltas) e faz `upserts.append` (:132); `didFullSync` continua false.
  3) Calendário B recebe 410 → `fullWindowedSync` e seta `didFullSync = true` (:141).
  4) Fim do loop: `isFullSync == true` → `store.replaceAll(resolvedUpserts)` (:162) com a lista combinada = poucos deltas de A + janela cheia de B.
- Esperado: eventos inalterados de A permanecem no EventStore; só os do calendário que fez full-resync são substituídos.
- Observado: `replaceAll` troca o store inteiro (ARCHITECTURE.md:71 = "full sync"), então todos os eventos inalterados de A são despejados. A ainda tem syncToken válido, segue na lane incremental e NUNCA os readiciona → perda de dados durável, alertas de reunião de A param silenciosamente. (Sync frio inicial — todos sem token → todos full — está correto; só o caso misto corrompe.)
- (resolvedor) Correção [Auth/Sync worker, per decisão Diego]: fixed — `store.replaceAll` REMOVIDO do caminho de sync. Reconciliação incremental por event id: (1) todo item devolvido upserta em `store.apply(upserts:)` por id (singleEvents=true → id de instância); (2) item `status == "cancelled"` remove por id (via `partition`); (3) full resync só em: token ausente, HTTP 410 GONE (por-calendário), ou safety net 1x/dia (novo `SyncState.lastFullSync[calendarId]`; parse falho do sync_state já cai em SyncState() vazio → full frio); (4) o merge usa `store.apply`, cujo didChange notification re-arma o timer único e recomputa Próximas/Já passaram; (5) evento já iniciado e editado → upsert (UPDATE, não apaga); cancelado já iniciado → removido do histórico por id; (6) sync_state gravado atomicamente só quando `updatedState != previousState`, e `store.apply` só chamado quando há upserts/removals. Para calendários que fizeram full no ciclo, eventos obsoletos (no store mas ausentes do fetch fresco) são removidos comparando por `calendarId` — calendários na lane incremental mantêm tudo (sem mais perda de dados de A). Sem mudança em Core (usa só `apply(upserts:removedIDs:)`). `swift build --target Sync` verde.
