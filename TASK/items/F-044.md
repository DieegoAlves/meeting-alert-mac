# F-044 — PKCE code_verifier ignora falha de SecRandomCopyBytes → verifier de entropia zero

## F-044 | categoria: funcional | severidade: baixa | status: fixed
- Tela: Sources/Auth/PKCE.swift:7-11 (`makeVerifier()` descarta o OSStatus com `_ = SecRandomCopyBytes(...)`)
- Passos:
  1) Sign-in chama `PKCE.makeVerifier()`.
  2) `SecRandomCopyBytes(kSecRandomDefault, 32, &bytes)` falha (raro) e retorna status != errSecSuccess.
  3) O valor de retorno é descartado (`_ =`); o buffer segue todo-zero.
- Esperado: falha do RNG deve abortar o sign-in (lançar erro), nunca prosseguir com verifier fraco.
- Observado: em falha do RNG o `code_verifier` (e portanto o `code_challenge`) vira uma constante previsível, sem erro levantado — anulando a proteção do PKCE (quem interceptar o authorization code poderia trocá-lo por token). (Comprimento/encoding do verifier — 32 bytes → 43 chars base64url, dentro do RFC 7636 — e o challenge S256 em :14-16 estão corretos.)
- (resolvedor) Correção [Auth/Sync worker]: fixed — `PKCE.makeVerifier()` agora é `throws`: `guard SecRandomCopyBytes(...) == errSecSuccess else { throw AuthError.secureRandomFailed(status) }` (novo case em AuthError, com cópia LocalizedError; seguro — nenhum switch exaustivo externo sobre AuthError). `GoogleAuth.signIn()` chama `try PKCE.makeVerifier()`, então a falha do RNG aborta o sign-in em vez de prosseguir com verifier todo-zero. `swift build --target Auth` verde.
